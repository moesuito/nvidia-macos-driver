# Notes for AI assistants

## Fork Policy & Upstream Synchronization

- **Our fork (`origin`: `https://github.com/moesuito/nvidia-macos-driver`) has no restriction on AI assistance:** AI-assisted commits, branches, PRs, issues, and documentation are fully allowed here.
- **Never submit AI-assisted PRs, issues, or comments to `upstream` (`nullmoth/nvidia-macos-driver`):** Upstream's `CONTRIBUTING.md` rejects AI-written contributions without review, so keep all custom fixes, optimizations, and workspace rules in `origin`.
- **Periodic sync workflow with `upstream`:**
  1. Fetch upstream changes: `git fetch upstream`
  2. Merge or rebase `upstream/main` into local `main`: `git checkout main && git merge upstream/main`
  3. Preserve custom fork improvements (such as `vendor/nvenc` NVDEC/VideoToolbox optimizations and `AGENTS.md`) when resolving any merge conflicts.
  4. Re-run `python3 tools/test_tree_layout.py` and relevant component builds/tests, then push to the fork: `git push origin main`.

Notes:
- Keep Apple's `/usr/bin/clang`, `ld`, `xcrun`, `codesign` (Xcode 26.6) unshadowed by using `~/.local/opt/nvk-bin` rather than putting `~/.local/opt/nvk-tools/bin` on `PATH`.
- `build/build_release_inputs.sh` does **not** derive `NM_LILU_DEBUG_KEXT`, `NM_VIRTUALSMC_SRC`, or `NM_MACKERNELSDK` from `NULLMOTH_BUILD_ROOT`; export them explicitly if building `nmkbl`/`nmhda`/`efizip`:
  ```sh
  export NM_LILU_DEBUG_KEXT="$NULLMOTH_BUILD_ROOT/downloads/lilu-debug/Lilu.kext"
  export NM_VIRTUALSMC_SRC="$NULLMOTH_BUILD_ROOT/third_party/VirtualSMC"
  export NM_MACKERNELSDK="$NULLMOTH_BUILD_ROOT/third_party/MacKernelSDK"
  ```
- `build/build_release_inputs.sh` checks `git status --porcelain --untracked-files=no` and stops if tracked files (including `AGENTS.md`) have uncommitted changes. Commit local changes on a branch (or stash/restore `AGENTS.md`) before running release input builds.
